## SQL inventory and additive migration disposition

[`database.py`](../../agent_rewind/database.py) defines exactly five tables; no foreign keys, explicit indexes beyond primary/unique constraints, schema-version table or project column exists at the baseline. IDs are lowercase `uuid4().hex`; timestamps are floating-point epoch seconds. Generic `records.data` is JSON, not a typed relational run schema. Existing migration execution has no schema fingerprint/stamping guard.

| Legacy table and columns | Writers → readers | M1 treatment and invariants |
| --- | --- | --- |
| `records`: `id PK`, `kind`, `created`, `data` | `Database.add` from Engine/Experiments; `finish_run` rewrites run **and study** JSON → get/list, API, Engine, Experiments, compare | Retain IDs, source timestamps and JSON verbatim; add `resource_scopes` for both kinds and `run_index` only for runs. Convert index `created_at` deterministically to UTC without overwriting original float. Reject unmapped kinds/owners; preserve same-project parent closure. AR-005/006/007. |
| `events`: composite PK `(run_id,step)`, `artifact`, `hash` | `save_event` inserts under job fence → `event_refs`, `read_events` | Append-only legacy rows and encrypted bodies retained. | `jobs`: `id PK`, `kind`, `created`, `payload`, `status`, `owner`, `lease_until`, `cancel`, `budget`, `reserved`, `result`, `error`, `actor` | enqueue/claim/fence/heartbeat/reserve/complete/cancel → worker, API, operations projection, tests | Retain queued/running/succeeded/failed/cancelled semantics; add resource scopes, operation association and hierarchical accounts. `budget`/`reserved` already integer micro-USD; preserve historic values. Admission and job scope must commit atomically; no new queue engine in M1. AR-005/007/008/010. |
| `api_keys`: `id PK`, `hash UNIQUE`, `role`, `name`, `expires`, `revoked` | issue/revoke → lookup on every bearer request | Keep token hashes/expiry/revocation; map project access explicitly, without deriving ownership from token names. | `audit`: `id PK`, `created`, `actor`, `action`, `target` | enqueue/cancel/key issue/key revoke, explicit API run.read and identity.login → no current query/export API | Preserve old records; no invented project attribution from opaque target without resource mapping. New scoped actions and admission records must be transactional. Tamper-evident export/retention is later AR-045, not existing functionality. AR-005/007/008/011. |

`Database._fence` requires matching owner, running status, unexpired lease and normally no cancellation, then extends lease to 60 seconds. `claim` uses `FOR UPDATE SKIP LOCKED` on Postgres; expired running jobs become failed rather than paid retry. `complete_job` checks owner/status/lease and chooses cancelled over success/failure when intent exists. The heartbeat thread catches `JobStopped` but not DB connectivity exceptions; elapsed lease guards remain at calls into Engine, not proof of prompt termination during every blocking action. `_fence` does not fence `add`, artifact writes or direct policy HTTP after a reservation. AR-017 must close those reliability gaps; the M1 ledger must not claim to deliver that entire slice.

M1 adds twelve logical entities: organizations, projects, project_memberships, resource_scopes, run_index, operations, operation_keys, artifact_objects, artifact_refs, budget_accounts, provider_calls and budget_entries. The proposal describes intended constraints; no executable DDL exists yet. Composite artifact and operation-key owner constraints are specified. Provider call/job project closure, budget account scope ownership and evidence-reference ownership still need explicit DDL or transactional enforcement fixtures in AR-004-B/010; independent foreign keys alone do not establish matching projects.

## Event, checkpoint and artifact identities

[`models.canonical`](../../agent_rewind/models.py) is UTF-8 `json.dumps(sort_keys=True,separators=(",",":"),allow_nan=False)` using Python's default ASCII escaping. `digest` is SHA-256 of those bytes. Byte-for-byte canonicalization is a compatibility boundary: do not normalize source text, alter Unicode escaping, change defaults or add fields to an already hashed historical body.

| Stored form | Existing producer / readers | Preserve or introduce |
| --- | --- | --- |
| Encrypted object | `Artifacts.put` hashes **plaintext bytes**, Fernet-encrypts with one configured key, writes local `objects/<64hex>` atomically or S3 `objects/<64hex>`. `get` validates identifier, decrypts, recomputes plaintext digest. | Keep current format readable as version 1. The hash is global content identity, not authorization. Add project-scoped object IDs/refs around legacy ciphertext; no re-encryption or KMS envelope in M1. |
| Task and admission payload | Canonical `TaskSpec`/branch/study/investigation dictionary; no object-level schema field. API writes payload; worker loads it; run `task_ref` allows branch reconstruction. | Keep original bytes/task digest. New v1 envelope and frozen adapter identity require explicit versioning and worker compatibility; do not make old TaskSpec readers parse a new envelope silently. |
| Workspace manifest | `{schema:1, files:{path:{blob,mode,kind,mtime}}}`; each blob has its own plaintext digest. `workspace` limits 10,000 entries and cumulative restored bytes, validates paths and masks modes. | Capture transitive manifest→blob ownership. Current byte limit is applied after each full blob read, not a bounded streaming download guarantee; AR-015 owns bounded I/O. |
| Checkpoint | `{schema:1,workspace,state,next_step,image,policy,seed,branchable}` before a tool decision. Engine writes; branch, files API and discovery read. | Preserve tool-boundary meaning and policy state; redacted state is explicitly non-branchable. No process memory, open socket, shell state or external DB snapshot. |
| Event object | Schema 1 with `run_id,step,previous,checkpoint,proposed,action,actual_result,observed_result,decision,workspace_after,changes,intervened`; `hash=digest(event_without_hash)` is added before artifact storage. | Event hash and artifact digest are **different identities**: the artifact includes `hash`. Keep SQL row's event hash, full object digest and checkpoint/workspace digests distinct. Tool-result edits retain actual filesystem effects while changing observed result. |
| Run manifest | `records.data` holds task/policy/image, job/parent/fork/seed, status, branchable, head, steps, intervention; completion adds success/evaluation/final workspace. | `complete` means execution/evaluation finished; `success:false` is a failed task suitable for debugging, not a failed execution job. New projection must preserve this distinction. |
| Branch ancestry | Parent events before `fork_step` are read recursively; child's own event rows start at fork step. Prefix events retain **parent run_id**; depth >64 rejected. Complete runs require final chain hash equal manifest head; running manifests may lag event write. | Validate inherited prefix ownership against actual ancestor, not child run ID. Backfill must not rewrite prefix events to child ID or require child rows for inherited steps. |
| Evaluation, job result, study report | Evaluation is encrypted JSON; job result is `{run_id}` or `{study_id}` encrypted JSON. Study report is mutable `records.data` with pairs/winner/protocol digest and uncertainty fields. | Map typed owner/role references and scoped result reads. Historical reports retain protocol/claim scope; no inferred normalized trial rows without later C08 conversion. |
| Identity cookies | Fernet-encrypted OIDC flow/session payloads use the **same configured key** as artifact encryption. | Key rotation must cover cookie invalidation/retained artifact readers explicitly in C07. Do not rotate key by overwriting a single env value and claim old artifacts remain readable. |

Local writes avoid overwriting an existing hash path; S3 writes replace ciphertext at the same hash key. Fernet ciphertext is randomized, so equal content need not have equal ciphertext. Current storage has no object-reference registry, deletion/GC, multipart/bounded streaming API, native GCS client, ciphertext envelope key ID or rotation. The v1 scoped handle must resolve historical embedded hashes through the owner's authorized graph; adding rows for only top-level artifacts is insufficient. `doctor` health objects and uploads followed by DB failure can be unreferenced. M1 must retain and identify those without treating them as deletable customer data; AR-032 owns later GC.

## M1 consumer compatibility policy proposed for review

1. **Adopt known baseline only.** Drain all legacy API/worker/CLI writers, make verified backup, fingerprint the exact known schema, then explicitly map legacy resources to one installation project. Unknown schemas, missing owners, broken ancestry and ambiguous artifact references block adoption. Additive revisions/backfills must be resumable and preserve historical bytes/hashes. Readers need explicit compatible revision ranges; restoring a backup is required when an unsafe downgrade is unsupported.
2. **Keep the legacy workbench/SDK/CLI contract.** During M1 they continue using legacy shapes through scoped repositories. Restrict each legacy caller to an explicitly resolved project and deny ambiguous/unmapped access. Scope all read, compare, branch, study, job, key and cancel paths before enabling a second project. Do not union every accessible project into a context-free mutation endpoint. A legacy deployment with a single mapped project can remain supported without pretending its consumers accept v1 shapes.
3. **Introduce v1 in parallel.** The pending API contains five operations: list/submit runs, read run summary, read operation, cancel operation. `RunSummary` deliberately lacks legacy `name`, `steps`, `success`, `policy`, events and evaluation; replacing the browser endpoint with it breaks current rendering. AR-027-A owns the richer history/UI contract. Keep RunSummary small until that consumer review; do not silently expand it here.
4. **Preserve a single CSRF header.** Current browser and Auth use `X-Rewind-CSRF`; the proposal says `X-CSRF-Token`. Recommended AR-004-B disposition is to use `X-Rewind-CSRF` consistently in v1 and legacy routes, retaining Origin validation. This is an unresolved draft change in this PR, not implemented behavior. Both auth methods remain alternatives; cookie mutation protection must not be disabled by merely documenting bearer keys.
5. **Admit atomically, execute once per logical request.** v1 separates integer budget/seed from TaskDefinition and introduces client operation ID plus key. Resolve defaults before canonical digest, freeze native adapter policy identity, authorize current access on every retry, commit job/operation/key alias/scope/audit together after verified upload. Preserve same returned IDs; never replay a paid call based on an ambiguous timeout. Existing SDK retries remain caller responsibility until AR-030.
6. **Maintain actual state semantics.** Operation status comes from job state, cancellation flag from intent; result_run_id requires authorized decrypted result. Failed task evaluation can coexist with succeeded operation. Lease expiry means incomplete execution even if stale manifest still says running. Reconciliation/read policy for stale manifests must be explicit; do not label them complete merely to enable a branch.
7. **Keep content identity separate from access.** Every nested hash read must be reached through a scoped owner, including parent prefixes, evaluator result, job payload and repeated identical bytes in separate projects. Equal hashes never confer cross-project access. Don't expose encryption locators as bearer access tokens. Keep old hashes in event bodies.
8. **Do not promise mixed-version concurrency prematurely.** Baseline workers directly insert generic records and blobs without new ownership, operations or ledger state. M1 activation requires draining those writers or an explicit compatibility bridge with tested invariants. No such bridge exists today. The bounded migration target is one organization with native adapter; external importers and future SaaS are unsupported until separately contracted.

## Validation evidence and limits

`python3 scripts/check_m1_contracts.py` validates local JSON references, unique operation IDs, path bindings, security-scheme references, required-property declarations, TaskDefinition field parity with the actual TaskSpec AST, and complete mapping of four response schemas to declared logical/legacy fields or explicitly derived values. It reports **5 operations, 41 internal references, 12 logical entities, 5 legacy tables, 20 directly mapped projection fields and 2 derived fields**.

`python3 -m unittest discover -s tests -p test_contract_inventory.py -v` passed **9 checks**: current mapping plus broken reference, new unmapped response field, removed logical column, path mismatch, TaskSpec drift, duplicate operation ID, unknown security scheme and mismatched baseline rejection. The CI-style console entrypoint `pytest -q -p no:cacheprovider tests/test_contract_inventory.py` also passed all 9 checks; the test loads the checker from its resolved repository path so it does not depend on the runner adding the repository to its import path. These are design-time regression checks, with no DB/container/provider startup and no dependency installation. Ruff lint and formatting passed for the checker/tests, all local document links resolved, and `git diff --check` passed. The existing installed environment also accepted the proposal through `fastapi.openapi.models.OpenAPI.model_validate`; that is structural model validation, not proof of all OpenAPI semantic rules.

This checker is intentionally not a complete OpenAPI/JSON Schema validator, SQL migration runner, semantic cross-field validator or authorization test. It checks mapped persistence fields, not correctness of every prose constraint or transaction. The 24 CT-M1 behavioral cases remain planned. AR-012-A extends this same checker with proposal-only approval checks, explicit acceptance links, bounded historical fixture verification and optional installed-FastAPI validation; see [the harness contract](M1_CONTRACT_HARNESS.md). Its general inventory API remains approval-neutral. Future executable runtime contract tests remain AR-012-B work. TL/QE consumer review of this inventory remains required before closing AR-004-A. Production readiness, real IdP/cloud storage/lease failure behavior and full migration correctness remain unverified by this task.
